接入真实 DeepSeek API，替换假批改器

批改链路：
- prompt.ts：提示词与返回格式的唯一真相来源。含字段格式、五种改法、
  错误分类表与判定优先级、评分标准
- parse.ts：解析 AI 返回的 JSON。结构不合格时给出可重试的具体原因，
  而不是笼统报错；解析后仍走一遍位置校验
- ai.ts：DeepSeek 调用（JSON 输出模式）、最多 3 次重试、失败分类
  （密钥无效 / 余额不足 / 限流 / 超时 / 网络 / 返回被截断 / 返回不是 JSON）
- vite-plugin-judge-api.ts：本地 /api/judge。浏览器代码里永远不出现密钥，
  请求由服务端补上密钥再转发；部署到 Workers 后同一路径由 Worker 承担
- client.ts：前端调用封装；App 改为异步提交，含批改中状态与分类错误提示

密钥处理：只从 .dev.vars 读取（已 gitignore）。全库搜索无密钥痕迹。

提示词中两条硬性要求来自实测教训，不可删除：
- 必须逐字核对字符序号并回查 snippet 与区间的对应关系
- 英译中的译文必须使用中文全角标点
位置校验器还会对"只差一个字符"的近失给出精确差值，让重试真正有用。

验证：
- npm run smoke 41 项检查全部通过（新增模拟批改接口的渲染测试）
- 三个真实用例实测通过，位置与分类准确；一例 AI 返回坏 JSON 自动重试成功，
  一例 AI 数序号少算一个字符被位置校验拦下
- 通过本地接口端到端实测 10.8 秒完成
- npm run typecheck 与 npm run build 通过

内置示例批改保留为「查看内置示例批改」入口，供没有密钥时先看效果。
