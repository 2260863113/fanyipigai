# 公网部署下用「全局口令 + 长期登录凭证」，而不是账号系统

网站部署在公网，且后端持有真实的 DeepSeek API 密钥。访问控制取最简形态：环境变量里存**一个**全局口令，输入正确后下发一个长期有效的登录凭证（浏览器保存），此后不再要求输入。**没有**注册、邮箱、找回密码、多用户隔离。

## 为什么

单人使用。账号系统要解决的是"多用户之间不互相看到数据"和"忘记密码怎么办"，而这两个问题在这里都不存在。真正需要挡住的只有一件事：**陌生人发现这个网址后拿去刷爆 API 余额**。一个足够长的口令加上"输一次记住很久"，就以最低成本解决了这个唯一的真实威胁。

## 连带影响：数据存在服务端而非浏览器本地

同一决策的另一半是：练习记录存在服务端 D1，而不是浏览器本地存储。原因不是备份，而是**设备间同步**——练习要在手机、平板、电脑之间切换，若记录只存在浏览器里，手机上练的和电脑上练的是两条互不相干的记录。

代价是：口令泄露即等于所有人共享同一份练习记录（无用户隔离），且没有任何找回机制（口令忘了只能改环境变量重设）。这在单人场景下可接受，一旦将来真的要多人使用，这一层必须整体重做。
