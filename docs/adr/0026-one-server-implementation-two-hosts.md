# 服务端一份实现、两个宿主；口令门缺配置就拒绝

> **后续补充（2026-09-25，见 ADR 0027）**：这道口令门已经**整个拆掉**了——
> 用户要求"去掉进入口令这一环节，任何人都可以访问"，于是 `gate.ts`、`session.ts`、
> `pages.ts`、`login.ts`、`logout.ts` 全部删除，Cloudflare 上那两个 Secret 也删了。
>
> 下面关于口令门的一切（fail-closed 的取舍、签名 cookie、常量时间比对）**不再是当前的实现**，
> 但它记录了当时的完整理由，而且**想收回门时照这个做就行**（`git revert` 提交 `50b7622`）。
> "一份实现、两个宿主"那部分不受影响，仍然是当前的做法。

## 决定

三个 AI 接口（`/api/judge`、`/api/refine`、`/api/generate`）**只有一份实现**，
放在 `src/server/api.ts`。它不碰文件、不碰 `process`、不 import `node:*`，
因此 Node（本地 Vite 开发服务器）与 workerd（线上 Cloudflare Pages Functions）都能跑。
两边各自只提供宿主特有的那几件事，用一个 `ApiHost` 摆在明面上：
领域模块从哪儿来、密钥从哪儿来、日志往哪写、失败记录往哪存。

线上由 `functions/` 下的 Pages Functions 承载：`_middleware.ts` 是门口那道闸，
`login.ts` / `logout.ts` 是登录与退出，`api/*.ts` 是三个只把请求读出来、把结果写回去的薄端点。

访问口令门**缺配置时拒绝一切请求**（fail-closed），并在页面上点名缺的是哪一个变量。

## 为什么要抽这一层

原先这三条链路**只存在于 `vite-plugin-judge-api.ts`**——那是 Vite **开发服务器**的插件，
只在 `npm run dev` 时存在。于是"线上怎么批改"一直是空的（README 的「尚未开始」里写着它），
而那台 Cloudflare 项目上线后能打开的只是一个**没有后端的壳**：能选题、能写译文，
一按「提交批改」就失败。

补上线上那一半时，最怕的不是写不出来，而是**写成两份**。这个项目已经吃过一次同类的亏：
改 `src/domain/prompt.ts` 之后行为不变，因为 dev server 是启动时把整个领域模块图加载进来的，
服务端一直在用改动前的旧提示词（见那个插件里的长注释与 ADR 记录）。
线上若再留一份独立实现，症状会更深：**只在线上出现、本地永远复现不了**。

因此切法是"按宿主切，不按功能切"：凡是"接口该怎么做"的逻辑全在共用实现里，
宿主只回答"我这边这些东西从哪来"。冒烟测试里有一条**函数身份**断言
（`plugin.isCorrectionRequest === shared.isCorrectionRequest`）：
行为测试拦不住"抄了一份、恰好还没改坏"，比身份才拦得住。

## 口令门：为什么缺配置时选择"打不开"

`ACCESS_PASSWORD` 或 `SESSION_SECRET` 缺失时，站点拒绝一切请求并显示"服务端还没配置好"。

另一个选项是**放行**（站点照常打开，只是没保护）。不选它的理由是两边的失败代价不对等：
放行意味着"忘了配"会静默变成**一个谁都能用、且花站主 API 余额的公开站**——
发现它的方式是收到账单；而拒绝只表现为"站点打不开"，一眼就知道是配置没做完，
去补一个变量就好。宁可让站主打不开自己的站，也不让陌生人花他的钱。

登录凭证是**签名 cookie**（`v1.<过期时间戳>.<HMAC-SHA256>`，30 天，`HttpOnly` + `SameSite=Lax`）。
过期时间写在浏览器拿着的那串里，因此**签名才是它的全部意义**——没有签名，
谁都能把它改成一个遥远的未来。口令比对与 cookie 校验都做成**常量时间**：
早退会通过响应快慢泄露"前几位猜对了没有"。

`Secure` 属性按请求协议决定（https 才加）：本地 `wrangler pages dev` 是 http，
加上它浏览器就不回传，现象是"口令输对了却一直退回登录页"。

## 放弃了什么

- **不引 `@cloudflare/workers-types`**：Pages 按**导出名**认端点，不需要 import；
  引了那套全局类型会与前端那份 DOM 类型打架。代价是 `PagesContext` 要自己写一遍结构类型
  （二十行，且没有任何运行时依赖）。
- **不引 session 库**：用到的只有"比一串口令、签一个 cookie"，两边运行时都有 WebCrypto。
- **`functions/` 里不放共享代码**：那里每个文件都是一个路由，
  放个 `host.ts` 就等于开了一条 `/host`。因此共享代码一律在 `src/server/`，
  `functions/` 里只留真路由与 `_middleware.ts`。
- **不给界面加登录按钮**：凭证是 `HttpOnly` 的，脚本读不到也删不掉，只有服务端能清。
  退出做成 `/logout` 这个地址，界面因此完全不需要知道"登录"这件事存在。
- **不做 D1、不做登录失败次数限制**：D1 是另一件独立的事（题库与练习记录仍在这台浏览器的
  localStorage 里）；失败次数限制要引状态（Durable Object / KV），当前规模不值当，
  失败只记一条日志（`[login] 口令不正确`），让站主看得见有人在猜。

## 线上失败存档：只能进日志

本地把失败记录写进 `.ai-failures/`；workerd 没有文件系统，只能 `console.error` 两行——
一行给人扫的摘要、一行完整的 json（能直接喂给 `scripts/failures.mjs` 那套分析）。
两条路径的记录形状**刻意完全一致**（`buildFailureRecord` 一份实现），
否则从线上日志里读到的证据会比本地的少一块，拿它改提示词会得出不一样的结论。

也正是为了这件事，`FailureCollector` 与记录形状从 `archive.ts` 拆到了
`failure-collector.ts`：`archive.ts` 里那句 `await import('node:fs')` 运行时被 try/catch 兜着没问题，
但**打包器在构建期**解析不到 `node:fs` 会直接失败——线上能不能跑，不该由这一句决定。

## 怎么验证的

- 冒烟测试 37 项新的检查：口令比对（对/错/空/长度不同）、凭证（过期、改过期时间、
  改签名、换密钥、版本号不认识）、cookie 解析（前缀相同的不许含糊匹配）、
  放行判定（缺配置、登录页、退出入口、页面与接口分开处理）、以及**直接调 Pages 端点**
  （GET → 405、坏 JSON → 400、段数对不上 → 400、没配密钥 → 503 且提示指向 Cloudflare）。
  最后那几条不发网络请求、不花钱。
- 本地 `wrangler pages dev dist` 起真实 workerd：没登录访问首页 302、
  静态资源也挡在门后（没登录连 JS 都拿不到）、口令错 401、口令对 303 并拿到 cookie、
  带 cookie 首页 200、退出后再进不去。
- 一次**真实批改**穿过 Pages Function 打到 DeepSeek：200，6.1 秒，1 处错误（`verbosity`），
  批注位置与 `sourceText` 都定位成功——证明 workerd 里 fetch、解析、校验、日志整条链路通。
