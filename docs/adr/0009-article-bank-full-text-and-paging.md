# 文章库改成收录**全文**，并按 100–200 一页切开

文章库（ADR 0007）原先是"每格 3 篇**选段**，每段刚好落在赛制篇幅内"。现在改成：**每格 6 篇英译中 + 6 篇中译英的整篇全文**，练习时由程序按 **100–200 单位一页**切开（英译中计词、中译英计汉字），用户一页一页译完整篇文章。

## 为什么要改

原来的口径有两个问题，都是用户实际用下来才暴露的：

1. **用户永远只能做"文章的一部分"。** 选段是"从正文开头累加到 250–350 词"，那一篇真正的其余部分用户根本看不到，做完也谈不上"练完一篇文章"。
2. **赛制篇幅被当成了练习篇幅。** 篇幅限制是**考场**的要求（一次交卷 250–350 词），不是**练习**的要求。练习时把整篇做完、一页一页交，才是真正的"逐段翻译"训练。

因此现在**不再按赛制篇幅截断**：库里存全文，界面上也不再拿"符合赛制篇幅"去标卡片——那是考场的事。

## 分页规则（用户给的数字，别随手改）

| 规则 | 数字 | 出处 |
| --- | --- | --- |
| 一页的目标带宽 | 100–200 单位 | "要求保证每一页在 100-200 字" |
| 段落不足下限时 | 与后面的段落并成一页，直到超过 100 | "如果一段不足一百字，那么一页显示两段甚至三段" |
| 段落超过绝对上限时 | 按**句子**切开（切点只落在句末标点上） | "如果某一段超过 300 字，那么合理分割将其变成两段" |

实现是 `domain/sections.ts` 的 `paginateArticle`，三条硬约束由 `scripts/check-articles.mjs` 对**整库 96 篇**逐篇验：

- 任何一页都不超过 300（越界说明该切的没切）；
- 最后一页不是"小尾巴"（不足 100）；
- 页与页之间只隔空白，拼起来一个字不丢。

现状（96 篇、698 页）：**87% 的页落在 100–200**；另 94 页在 201–300（单段本身就有 200–300 单位，按规则"超过 300 才切"，它只能自己当一页）；不足 100 的 0 页。

## 页不再是"一个自然段"

这是这次改动里**最容易踩**的一处：`页` 以前就等于"一个自然段"（`splitSections` 按空行切），现在它是"若干自然段拼起来的一段，或者一个超长段落切开后的一半"。因此：

- `sections.ts` 同时保留 `splitSections`（按自然段切，仍是分页的**输入**）与 `paginateArticle`（按页切，界面与提交用的都是它）；
- CONTEXT.md 里 `页` 的定义跟着改了；
- 提交给批改接口的仍然是"这一页的原文分段 + 这一页的作答"，页与页之间互不影响。

## 顺带修掉的一个真 bug：批注坐标被整篇平移过

逐页提交时，`answerSections[0].start` 原先填的是"这一页在整篇里的位置"。而服务端会**按这个起点把批注平移之后再返回**（`mergeSectionCorrections`），界面却拿"这一页的文字"去画勾画——于是**第 2 页以后的批注整体被推出这一页**，勾画一处都画不出来，而分数、清单照常显示，界面上完全看不出哪里不对。

实测（`scripts/probe-section-offset.mjs`）：同一份作答 `start=0` 时报 17–30，`start=50` 就报 67–80。

现在一律填 0：逐页提交一次只发这一页，服务端重建出来的那段文字**就是这一页**，0 才是它真正的起点。`verify-per-page.mjs` 里加了"每一次请求的答案起点都是 0"的断言。

## 版权口径跟着放宽了一点（仍然只收官方媒体）

ADR 0007 定的口径是"只存截取的连续片段，不存全文"，理由是避免把商业媒体正文放进公开仓库。现在既然要存全文，就明确划一条线：

- **只收中国官方媒体**：新华英文、中国日报、CGTN、人民网英文、gov.cn、china.org.cn；中文侧是新华社、人民日报、中国政府网、光明网、求是网、教育部。
- **不收任何商业媒体**（路透、BBC、卫报、AP 等）——那类正文进公开仓库的版权风险明显更高。
- 每篇保留**真实 URL** 供溯源与人工复核，正文照抄、不改写。

## 数据怎么维护

96 篇全文加起来五十多万字符，因此正文放进两个**自动生成**的数据文件：

```
src/domain/articles-data/en-to-zh.ts   ← node scripts/fetch-articles.mjs --write
src/domain/articles-data/zh-to-en.ts   ← node scripts/fetch-articles-zh.mjs --write
```

`domain/articles.ts` 只保留类型、领域表、查询函数与汇总，因此别处 `import ... from './articles'` 一个字都不用改。`scripts/check-articles.mjs` 是这套数据的验收口：篇数、完整性（不许以省略号结尾、不许混进页脚）、不雷同、分页体检，四项一起看。
