# 术语库整批换成两份机关名称材料：归档旧词、题号换代、旧数据一次性清理

## 决定

术语栏的题库整批换掉：源材料变成仓库根目录的**两份 docx**
（`国内机构.docx` 83 条「国内机关名称」、`国际机构.docx` 60 条「国际机关名称」，合计 143 条），
正文由新脚本 `scripts/build-terms.mjs` 现算成 `src/domain/terms-data/*.ts`——
与**文章库**同一套做法（材料进仓库、正文重算、生成文件顶上写着"不要手改"）。

连带四件事一起定下：

1. **旧术语归档**：原来那 43 条按话题领域分组的政论术语（外加 9 条从未启用的古文名句）
   搬进 `src/domain/legacy-terms.ts`——数据留在仓库里、**不被任何代码 import**。
   "归档"在这里的意思就是这两件事同时成立：**不丢**（不用翻 git 历史）且**不进应用**。
2. **题号换代**：`term-v2-<领域>-<第几组>` → `term-v3-<范围>-<方向>`。
3. **一个范围 = 一道题**（不是一个五条的小组），页号就是 `sectionIndex`，
   因此逐页批改那一整套（翻页不提交、批过的页只读、返回编辑、批改记录、进度、从没批完的那页继续）
   **一行都不用改就白拿了**（用户的要求原话就是"像文章模式一样一页一页翻，每页五个术语"）。
4. **旧数据一次性清理**：换代之前的术语**记录与收藏**都清掉，
   判据是旧代次前缀（`term-v2-`），因此新代次的记录在结构上不可能被它命中——
   "以后我留下的术语记录不会被自动删掉"这句话是**判据**保证的，不靠"只跑一次"这种约定。

## 为什么

用户在第 13 轮直接给了材料（两份 docx）与一句话："归档目前存在的所有术语，引入目录国内国际机关 docx 文件，进行导入。"

值得记下来的是两条**取舍**：

- **归档而不是删除**：那 43 条词（高质量发展、共同富裕、新质生产力……）是好东西，
  删了就只能翻 git 历史。用户选的是"从术语栏整个撤下，数据文件留在仓库里当档案"。
  代价是仓库里多一份不再被引用的数据——因此**它不许被 import**（一个没有 import 的模块不进打包体积，
  这正是"归档"与"还在用"的分界）。
- **旧记录与旧收藏清掉而不是留着**：记录与收藏都**不存题干**（只存题号，原文靠题号回查），
  换代之后旧条目会变成一批点开没内容的空壳。用户先问清了"删掉是什么意思"，
  然后选的是"删掉我之前留下的术语记录，未来我留下的术语记录不会被自动删掉"。

## 连带的几件事

1. **术语栏的两个控件**：「范围」按钮（弹窗两屏：两张范围卡片 → 一张大卡片里的中英对照平表 +
   「确定／返回」）与「中译英／英译中」两段按钮，都放在**原文栏标题栏、紧挨「原文」右边**——
   与文章栏的「领域 × 方向」同一个位置（用户要求"模仿文章模式"）。
   术语栏的「换一换」与「AI 出题」**一起撤掉**：术语只来自两个范围，
   AI 现出的术语既没有范围也没有页码，翻页与最高分在它身上都无从谈起。
2. **方向两侧都能练**：每条术语两侧都有（中文名 + 官方英文名），因此两个方向**永远可点**，
   不像文章栏那样要按"这一格有没有材料"禁用。
3. **本地判分不再借用"内置示例"的身份**：早先术语判分写的是 `source: 'fixture'`，
   于是顶栏那枚「内置示例批改」警告**每次术语批改都冒出来**（用户报的就是这个）。
   现在它有自己的来源 `local`（见 `types.ts` 的 `JudgeSource`），
   顶栏那枚芯片整枚删掉，示例批改的提醒搬进结果栏。
4. **自定义栏的"贴一篇"弹窗一并删掉**（同一轮的另一条要求）：原文栏自己就是输入框，边写边存。
   为它配套的三条：题号**只铸一次**（每敲一个字换题号会把作答与记录全丢掉）、
   `loadCustom` 允许原文为空（"还没开始写"是正常状态）、
   以及"**已经练过这一篇之后再改原文**就当成一篇新题、铸新题号"——
   否则不存题干的旧记录会跟着新原文改口。
5. 术语栏的页脚翻页、页状态、`article-progress`、落点记忆全部与文章栏共用同一份实现。

## 代价

- **对照表就是把答案摊开**。用户对范围大卡片的要求是"中英文都列出来（等于一份对照表）"，
  并确认练习中点「范围」也能重新打开它。这不是漏洞，是选的：那批机关名称本来也是资料。
- 旧术语记录与旧收藏**真的没了**（一次性、不可撤销）。数据只落在 git 历史里。
- 旧代次的记录页/收藏页从此解析不出题干——因为条目已经被清掉了，所以界面上不会留下空壳。
