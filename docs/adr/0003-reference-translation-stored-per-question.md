# 参考译文随题目生成一次并存库，不随每次批改重新生成

一道题目的参考译文在第一次被打开时由 AI 生成，随后存入题库长期复用——包括同一道题被重做时，用的仍是那一份。参考译文不是「批改的副产品」，而是**题目数据的一部分**。

> **后续补充（重要）**：参考译文**只给人看，不发给模型**。
> 批改请求里只有原文与学生的译文——把它发过去，模型会退化成"逐字对照标准答案"，
> 与"允许合理意译"的判断口径直接打架。因此这份数据的作用是：给用户自查、
> 给「对照视图」当参考，而不是当批改的输入。

## 为什么

比赛真题本身不提供参考译文，所以这份"标准答案"必须由 AI 写。真正的问题不是谁来写，而是**它能不能变**。

如果每次批改都现生成一份，用户就无法判断"上次 75 分、这次 80 分"是因为自己进步了，还是因为这次的参考答案更容易达到。分数失去可比性，"重做同一道题"这件事也就失去了意义。同时它还带来重复的 API 花费。

## 代价

代价是放弃了「同一道题能看到多种表达」的学习价值。这是有意的取舍：**可比性优先于多样性**。想学多种表达时，靠的是批改里"精修"档提供的更优表达，而不是让参考答案本身漂移。
