# 第 18 轮：手机端只留「原文 · 输入框 · 底部操作栏」三样东西

> **状态**：已落地。这一条记的是**手机端版式**这一个决定，以及从它派生出来的几个必要的取舍。
> 涉及的文件：`src/styles.css`（末尾那一段 `@media (max-width: 600px)`）、
> `src/components/useIsMobile.ts`、`src/components/MobileSidebar.tsx`、
> `src/components/AccountControl.tsx`、`src/components/SourcePane.tsx`、
> `src/components/AnswerPane.tsx`、`src/components/App.tsx`、
> 以及验收脚本 `scripts/verify-mobile.mjs`。

## 决定

1. **手机端的判据是 `≤ 600px`，并且与老的 `900px` 那一档并存**：
   `601–900px` 照旧走"四栏上下叠放"那套旧窄屏版式，一个字没动；
   `≤ 600px` 走这一轮新做的手机端版式。**桌面端（>900px）一个字都没改**。
2. **手机端在结构上只做三件事**：最上方只剩「三条横线 + 标题」，两栏上下叠放，
   底部一条两行的操作栏。原文栏与译文栏之间**只有一条分割线**。
3. **编辑模式与批改视图是两套高度**：编辑模式两栏**各占屏幕高度的 1/4**、整页锁死不滚；
   批改视图两栏**完全展开、有多长就多长**、整页可以滚。
4. **手机上不画「总体评分」与「批注详情」两栏**（在结构上就不渲染，不是藏起来）。
5. **导航栏的所有东西搬进侧边栏**（左上角三条横线点开，从左边滑出）。

## 一、为什么是"另做一版"，不是"把桌面端挤窄"

这一条与 ADR 0031（版式靠测量）是**同一件事的两个方向**。0031 定的口径是：
凡是"两样东西要一样高 / 要一行装得下"，都**量一遍再落**，不写死数字——
因为答案取决于当帧的内容与窗口宽度。

手机端的要求里有几条**恰恰是写死的**：

| 用户的要求 | 为什么这里可以写死 |
| --- | --- |
| 原文栏与我的译文栏**各占屏幕的 1/4** | 它要的不是"看起来差不多高"，而是一个**硬保证**：剩下那半屏必须空着留给手机输入法。内容多长都不能把另一栏顶走，因此这一档**禁止整页滚动** |
| 两栏之间**只有一条分割线，不要有其他任何文字** | "不要有文字"是结构问题，不是量出来的：译文栏标题栏在手机上**整行不渲染** |
| 屏幕上**只出现三样东西** | 同上：总评栏与批注详情栏在手机上**根本不渲染**，而不是画出来再 `display: none` |

因此手机端不是"桌面端 + 一堆覆盖样式"，而是**另一套版式**：
结构上少画几块、多画几块（侧边栏、选择弹窗、底部操作栏），样式上另起一段媒体查询。
两边共用的是**领域逻辑与组件**（同一道题目、同一份批改、同一个 `AnswerPane`），
不是布局。

## 二、为什么断点是 600 而不是复用 900

项目里原先只有一条 `@media (max-width: 900px)`（四栏改成上下叠放、整页自由滚动）。
它的意图是"窗口窄了但还在用电脑"——导航栏、总评栏、批注栏**都还在**，只是排成了一列。

手机端要的不是这个。用户拍板的是**只改 600px 及以下**，理由是：

- 601–900px 这个区间里绝大多数是**平板与窄窗口的桌面浏览器**，它们有键盘鼠标、
  屏幕也够高，"每条翻页按钮都挪到底部、总评栏整个不显示"是**退步**；
- 而 ≤600px 是真正的手机，一条手臂的距离、拇指在底部、输入法会盖住下半屏。

**代价**：代码里因此有两条窄屏规则并存，改版式时要先想清楚"这一条管哪一档"。
两段的注释里都把这件事写明了。
**另一条必须记住的**：断点数字在**两个地方**各写了一遍——样式表里那句媒体查询，
以及 `useIsMobile.ts` 里那句 `MOBILE_QUERY`。前者管样式，后者管**结构**
（顶栏换成三条横线、两栏不渲染、原文栏那颗「选择」弹窗）。
写岔了就会出现半截状态（结构按手机来、样式按桌面来），因此两个文件里都标着"必须一致"。

## 三、手机端那三样东西是怎么定下来的

用户的原话是："最终效果是手机端上，用户可以自行调整，让屏幕上只出现三个东西，
从上到下依次是原文、输入框和用户手机输入法（考虑到手机屏幕小，
原文和我的译文栏目中间仅仅用一条分割线分割，不要有其他任何文字）。"

这句话里有两个约束会打架，因此分了两轮问清楚：

- "原文、输入框、输入法"要**同时**在屏幕上 → 上面两栏必须**各占 1/4**，
  剩下 1/2 空着（那一半系统输入法会盖上去）；
- 但用户又说"批改视图下我的译文和原文**完全展开，有多长就展开多长**"——
  那就必然要允许整页滚动，而整页能滚，"各占 1/4"就不再是硬保证。

用户选的是**分两档**：编辑模式严格锁死四等份，批改视图例外。这条分界线的判据只有一个
（`shown !== null && !editing`，也就是"屏幕上是结果"），它同时决定三件事：
两栏的高度档位、整页能不能滚、底部那颗按钮写「提交批改」还是「返回编辑」。
**一处判据、三处行为**是有意的：分别判三次迟早会判出"按钮写着提交、
屏幕上却是结果"那一类对不上的状态（第 6 条那次就是这么来的）。

## 四、手机上不显示总评栏与批注详情栏——代价

用户原话："对于手机端，不显示总体评分栏和批注详情栏。"
问过之后用户仍然选了这一条，代价因此**明确记在这里**：

- 手机上看不到**得分**（0–100）与**弱项统计**（错误归类那几行）；
- 也看不到**批注详情卡片**（哪段文字 → 改成什么 → 为什么）——
  只有点某一处时浮出来的那张**小卡片**，它写的是"这是什么问题、为什么"，
  **不写分数、不写"改前改后"**；
- 右下角那条「收藏」入口跟着没有落点（与术语模式同一个代价，见 ADR 0030 那一段）。

要恢复的话只有一条路：把这两栏**收进别处**（侧边栏或一个弹窗）——
但那是"换个地方显示"，与用户"不显示"的要求相悖，因此这一轮没有做。

## 五、几个必要的实现取舍

- **账号那一组控件抽成 `AccountControl.tsx`**：它原先只长在顶栏里，
  而手机端顶栏要换成侧边栏、侧边栏里照样得有账号入口。逐字抄第二份是这类代码
  最容易分家的地方（改一处漏一处只是时间问题）。抽出来时 **DOM 与类名逐字没动**——
  桌面端的验收脚本盯着 `.user-center` / `.user-menu` / `.account-button` 这几个类名。
- **侧边栏里那六颗题型按钮仍然带 `mode-tab` 类名**（文案与顶栏逐字相同）：
  手机端的验收脚本照桌面端那套选择器去点它，两边的"六个题型"因此是同一份数据
  （`VISIBLE_MODE_TABS`），将来加一栏不会只加一边。
- **「上一页 / 下一页」抽成 `MobileSectionNav`**：它在**三处**被用到，
  而且分属两个组件——`AnswerPane` 的底部操作栏与批改视图那条钉住的行，
  以及**术语栏**（术语题那一块在 `App.tsx` 里是单独渲染的）。
  第三处没接进来时，术语栏在手机上**一个翻页按钮都没有**（实测：批改视图下
  `[data-nav]` 找到 0 个）。
- **原文栏那条页脚在手机上不渲染**，而不是 `display: none`：
  藏起来的话同一页上会有**两套**「上一页 / 下一页」，验收脚本按
  `.section-nav [data-nav="next"]` 找按钮必然撞车，间距也会翻倍。
- **`dvh` 而不是 `vh`**：手机浏览器那条地址栏会被算进 `vh` 里，
  两栏各 1/4 会因此多出十几像素、底部操作栏被压到地址栏下面。
- **不去监听输入法高度**：用户选的是"按屏幕高度算一半，不管键盘"。
  因此也**没有**给 `index.html` 的 viewport 加 `interactive-widget=resizes-content`——
  加了之后输入法会真的压缩页面，反而会打乱这个固定布局。
  安卓上的实际效果是输入法盖住下半屏（那半屏本来就是留给它的），
  苹果 Safari 上同理，两边行为一致。

## 六、两个已知取舍

1. **原文一长就看不全**：原文栏固定 1/4 屏，长段落要在那一小格里滚。
   这是"各占 1/4"的直接代价，用户明确选了它（要的是输入框位置稳定、不被长度推着走）。
2. **手机上换题型要先开侧边栏**：题型导航只长在侧边栏里（用户要求"导航栏的所有东西挪到侧边栏"），
   因此从文章换到术语要开一次侧边栏、点一下。曾经考虑过在「选择」弹窗里再列一遍题型，
   用户否掉了（"题型导航只在侧栏里"）——同一件事两个入口，以后改行为时容易不一致。

## 影响

- 用户能看到的：手机上最上方只剩三条横线与标题；点三条横线开侧边栏（六个栏目 + 留言板 +
  账号 + 暗夜 + 设置都在里面，点一项就切过去并自动收起）；原文栏标题右边只剩一颗「选择」，
  点它弹出这一栏的全部选项；「我的译文」那一行标题没有了，翻页、提交、档位、批改记录
  都在底部两行操作栏里；编辑时原文与译文各占屏幕 1/4、中间只有一条横线；
  一交完卷两栏就展开、翻页那一行钉在译文栏顶部；弹窗占满手机屏宽、内部自己滚。
- 新增的验收：`node scripts/verify-mobile.mjs` **62 项**（真浏览器 375×667）。
  它的第 1 节专门对着 **1440×900** 量一遍"桌面端没有任何改变"——
  包括顶栏七项顺序、右侧仍是「账号 · 暗夜 · 设置」、总评栏与批注详情栏仍在、
  翻页按钮仍在**原文栏**、标题栏里那一组控件仍在、两栏仍是左右并排。
  其余各节逐条对着用户这一轮提的九件事。
- 连带改了两处脚本：`scripts/visual.ts` 里"界面挂载了没有"的旗子在手机尺寸下
  改成等 `.topbar-mobile`（手机上那六颗题型标签长在**收起的侧边栏**里，
  原先等的 `.mode-tabs` 根本不在 DOM 里，`04-mobile` 那一张因此报过"界面没有挂载"）；
  `scripts/shots.mjs` 与 `scripts/smoke.ts` 里那一张截图从 420×900 改成 **375×667**。
- 代价：见第四节（手机上没有分数与批注详情）与第六节（原文一长得在格里滚、
  换题型要先开侧边栏）。
