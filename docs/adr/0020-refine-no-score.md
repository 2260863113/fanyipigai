# 大改档取消分数与总评：全站只留一种分数

## 决定

**大改档不再打分，也不再给总体评语**。左下角那一栏只写一句"大改档不打分"，
练习记录与「批改记录」下拉里那一次标注为「大改 · 不打分」而不是一个数字。
`RefineResult` 里既没有 `score` 也没有 `comment`——不是值为 0，而是**没有这两个字段**。

## 为什么（用户的原话）

用户看过两档分数的并排显示之后说：

> 干脆这样，大改页面取消分数打分，分数打分只有精修部分有。这样语义相同。

追问"总评文字要不要留"时，他选的是**连文字总评也去掉**。

## 为什么这一条值得记下来

在这之前，本项目有**两种分数**，而且是被 ADR 0015 特意保留下来的：

- **精修档**：程序按错误列表算（`100 − 硬性×8 − 表达×3 − …`），可解释、可复算；
- **大改档**：模型按整篇印象给的 0–100，附一段"为什么是这个分数"。

代码里到处写着"两个分数**不可比**"（`ScorePane` 的「AI 总评」标记、练习记录里的
「大改 · AI 评分」标签、README 与 CONTEXT 的提醒）——这些提醒存在本身就说明这是个负担：
同一个 0–100 在两档下含义不同，用户还得先读一句说明才知道"换一档分数为什么会掉"。
把它删掉之后**全站只剩一种分数口径**，那句提醒也就不需要了。

## 连带的三件事

1. **「最高分」只看精修档**（第 12 条）：选文章的卡片上那枚「最高分 N 分」不再混入
   AI 印象分，语义与精修档的分数一致。没练过、没得分就写 0 分。
2. **「批改记录」下拉与练习记录**里，大改那一次写「不打分」而不是一个数字——
   留一个空白或 0 会让人以为是加载失败。
3. 左下角的标题从「总体评分」变成「大改档」，旁边挂一枚「不打分」的标记。
   **那一栏仍然在**（第 4 条的版式里它是"左下角"那格），只是内容从分数变成一句说明。

## 代价

- 大改档从此没有任何可比较的量化结果。用户想"看有没有进步"，只能自己读改写后的句子。
  这是他自己选的：他要的是**分数只有一个来源、且能自己核**。
- 老记录里存着 `refine.score`／`refine.comment`（JSON 里还在）。程序照旧能读、
  但**不再显示**——旧记录打开时看到的是同一个"不打分"，与其他大改记录一致。
- 提示词里少了两块输出。模型仍可能出于习惯返回 `score`/`comment`：
  解析器**照收但丢弃**（不至于因为多了两个字段就整份重试）。
