# 雷同片段不标色：改动块两端那截相同的内容也不划

## 决定

一处改动里，**开头或结尾**若有一截"改动前后逐字相同、达到 3 个单位、而且切点在两侧都落在单位边界上"的文字，
就把它从改动块里剪掉。例：`aaa bbb ccc dddd eee → hh bbb ccc dddd dee`，
只标 `aaa → hh` 与 `eee → dee`，中间那三个词**不划**。

用户的原话（第 6 条）：

> 目前已经实现用户译文和 ai 修改译文前后缀相同部分不标色，但是我希望，
> 对于中间内容相同的且相同部分大于两个字或者单词的雷同部分，也不标色。

追问"会不会和已钉住的 `At meanwhile → Meanwhile` 那条用例冲突"时，他的答复是：

> 注意：绝对不要出现某个单词按照字母拆开修改的问题，每个单词就是最小单位了。

## 单位是**完整单词**，因此那条老用例不受影响

- 英文只数**完整单词**：`At meanwhile → Meanwhile` 里两边相同的那截是 `eanwhile`——
  它是**半个词**，一个单位都数不出来，切点也落在词中间，两道判据都拒。因此那条用例
  仍然整段替换，预期值一个字没改。
- 中文按**字**。中文没有空格，所以实现里要把汉字排除在"词"之外——
  否则一整句会被当成一个词（这正是下面那个真实毛病的原因）。

## 真正的收益在中文侧（实测）

用户举的是英文例子，但**那个例子改前就已经是对的**：字符级 LCS 本来就把中间三个词留在块外
（实测改动前后输出完全一致）。这次改动真正吃到的是**中文**：

```
他们讨论了中国农业发展的问题 → 他们介绍了中国农业发展的问题
  改前：整句标色
  改后：只标「他们讨论 → 他们介绍」
```

原因是 `alignToWord`（按词扩到边界）在中文上**把一整句当成一个词**，
于是"只改了一个词"也变成"整句被替换"。这条毛病在 `refine.ts` / `compare.ts` 里早有注释提到
（"用批注口径的 minimizeChange 时中文整句会被当成一个词、只能整段染色"），
这一条把它在**批注**这条路上修掉了。

## 为什么裁剪是安全的

剪掉的那一截**两边逐字相同**，因此"把改动应用回去能还原成新文字"这条不变量照旧成立
（块变短、写入的新文字也相应变短，剩下的部分替换回去结果完全相同）。
实现把这条放在"各块互不重叠 + 能还原"两道判据**之前**：块剪短之后，
本来互相压着的两块常常就分开了，判据从"过不去、只能整段替换"变成"过得了、按几处精确改动画"
（随机对拍 5952 组：这类"整段替换收窄成精确改动"307 例，反向 0 例）。

## 边界：一处改动超过 2 项时仍然整段替换（**有意的例外**）

一处批注最多容纳 2 项改动，超过就整段替换（老规矩，见"最小修改"那一节）。
那种句子里，相同的文字夹在**两处**改动之间——裁剪只剪块的两端，本来就剪不到它。
唯一能让那种句子只标真正变的词的办法是把上限调大（实测上限 ≥4 时中间那三个词一个都不标），
但那是**对照视图**的口径（两行并排、切得越细越好）；批注是画在译文上的，
宁可整段重写，也不要画出一堆互相牵制的碎片。

这条边界**钉成了一条用例**（名字里写着"若有意的改动请先改这条"），
免得以后有人把它当成 bug 顺手改掉。

## 代价

- 英文侧几乎等于没有变化（纯英文随机样本 1979 组里裁剪一次都没触发：英文被空格切开，
  对齐走到空格就停，块里夹不住一整串相同的词）。中文侧变化明显（1953 组里触发 1299 组）。
- 会出现"这一处批注只标了半句、另一半留着"的画面。这正是用户要的：
  标出来的每一处都应该是真的需要改的地方。
