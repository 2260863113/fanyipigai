# 「批改记录」下拉取代「查看上次批改」，并且提交成功就把这一页收回只读

## 换掉了什么

译文栏标题栏原来有两样东西：一个「已改过 · 待提交」提示芯片，和一颗「查看上次批改」按钮。
用户要求："去掉'已提交'的提示，而是添加'批改记录'的下拉栏，
用户可以选择之前第几次的批改记录，点击后，显示当时的批改记录。"

于是：

- **删掉**那个芯片与那颗按钮（连同它们背后"把结果挪进暂存区、再点回来"的机制）；
- **新增**「批改记录」下拉：列出**这一页**之前每一次批改（最新在前，标"第 N 次 · 时间 · 分数"），
  选哪一次就把右栏切成那一次的结果（只读，不动正在写的文字），旁边给一个「回到作答」。

## 为什么旧按钮撑不住

它有一条自相矛盾的资格线：**只有"一个字都没改"时才出现**。
理由曾经是站得住的——批注的位置是按提交当时那段文字算出来的，草稿一改就对不上；
但结果是：用户**一旦真的动手改字，就再也看不到上一次批的是哪儿了**，
而那恰恰是他最想看的时候。

下拉读的是**落盘的练习记录**（`translation-practice.records.v2`），
里面存着那一次提交时的原文与作答，因此批注画的就是那段文字，永远对得上——
"改没改过字"这件事不再是个约束。代价是练习记录有条数上限（整站 100 条、满了丢最旧的），
很久以前那几次会被挤掉；这一点在下拉的注释里写明了。

## 顺带修掉一个真实存在的窟窿

写这个下拉时发现的：「返回编辑」会把这一页记进 `unlocked`，
而**此后再也没有任何路径把它撤出来**——于是用户改完、按了「提交批改（手动）」，
界面却仍旧停在作答框上、左边还写着"已修改 · 待提交"，**新结果明明已经存下来了却不显示**。
（旧版那颗「查看上次批改」也救不了：它要求草稿一字未改，而用户刚改过。）

现在提交成功会发一个 `pageLocked`：把这一页从 `unlocked` 里撤掉，重新回到"已批改"这一档，
显示刚批出来的结果；想接着改，再按一次「返回编辑」。冒烟测试与浏览器验收里都加了断言盯着他。

## 顺带清掉的死代码

`pageResultRestored`（"点回去看那份批改"）在新入口下**再也到不了**，因此删掉了；
`openResults` 仍然保留——它还有一件事要做：区分"放开了但一个字没改"与"放开了并且改过"，
这两档在界面上的说法（`PAGE_STATE_HINT`）与自动提交行为都不同（见 `components/AnswerPane.tsx` 的 `PageState`）。
