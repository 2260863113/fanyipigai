# 翻页不再自动提交：批改在后台跑，人可以翻页继续译

用户原话（第三版）：

> "点击下一页或者上一页，不触发提交批改，而是保留当前页面输入缓存，后面返回时可以继续作答"
> "即使在批改过程中，用户可以手动切换页数，继续翻译（但是批改过程中不能提交）"
> "当批改结果出来时，右下角弹出信息通知'第x页已经批改完成'，用户可以点击该通知直接路由到那个页面，也可以手动翻页翻到前面"
> "点击提交批改后，弹出窗口'批改大约需要一分钟，等待过程中，可进入下一页继续翻译'，下面有两个按钮'停留此页''进入下一页'"

这一条**推翻 ADR 0008 的第 1 条**（"离开一页时自动提交那一页"）。0008 的其余各条（结果按页存、批过的页只读、
返回编辑才可写、提交之前钉死目标）全部保留。ADR 0008 从此在"翻页会不会提交"这一件事上作废，其余仍然有效。

## 为什么推翻它

自动提交当初的理由是"用户的动作就是写完翻页，提交夹在中间符合直觉"。真跑起来之后，这个直觉是**反的**：

- 用户翻页只是想看看下一页的原文有多长、或者想回去对一下上一段，**这个动作本身不表示"我要交这一页"**；
- 而它会花钱（一次批改几分钱）、会等待（十几秒到一分钟）、还会**把他锁在原地**——
  旧版在批改期间禁用「上一页 / 下一页」，于是"翻一下看看"变成"必须等它跑完"；
- 更糟的是"改过没有"这件事成了翻页行为的开关：用户既看不见这个开关，也无从预测翻页会不会扣钱。

改成"只有按「提交批改」才提交"之后，**提交这件事只有一个触发点**，用户对成本与时机有完全的掌控。
代价是"忘按"——用户可能写完一页直接翻走，那一页就一直没批。这个代价用**状态文案**兜住
（翻页导航中间写着"待批改"，翻页按钮的悬停说明写着"这一页还没提交，草稿会留着"），而不是用自动提交兜住。

## 随之而来的四件事

1. **`PageState` 从四档变成四档，但含义全换了**：`pending` / `judging`（新）/ `graded` / `editing`。
   原先的 `edited` 与 `modified` **合并成 `editing`**：那两档的唯一用处是决定"翻页要不要自动提交"
   （见 0008 第 21–28 行），自动提交没了，它们就不再改变任何行为，留着只会让状态机看起来比实际复杂。
2. **正在批的那一页只读，但翻页不拦。** 提交之后这一页的作答框变成 `readonly`（这一刻改字，
   回来的批注就画在对不上的文字上了），但「上一页 / 下一页」照样能点——这正是用户要的
   "等待过程中可进入下一页"。
3. **一次只批一页。** 批改期间提交按钮按不动（正在批的那一页写着"批改中…"，别的页上禁用并注明
   "正在批改另一页，等这一页批完再提交（一次只批一页）"）。因此"正在批改"再也不能是一个布尔量：
   它必须记成 **`judgingTarget = {题号, 页号}`**，才能同时回答"这一页在批吗"（进度条与只读）
   与"别处占着这次调用吗"（提交按钮）这两个不同的问题。
4. **批完要喊人一声。** 既然允许交了就走，结果回来时就得有人叫他：右下角弹一条
   「第 x 页已经批改完成」，**点它跳到那一页**；人自己翻到那一页时它自动消失（已经站在那儿了，
   还挂着"点这里去看"就是废话）。这条通知同时只可能有一条——一次只批一页，因此不需要队列。

## 提交之后的那个等待窗

提交成功**立刻**弹一个窗："批改大约需要一分钟。等待过程中可进入下一页继续翻译……"，
下面两颗按钮「停留此页」「进入下一页」。它存在的唯一理由是**把"你现在可以走"这句话说出来**：
没有它，用户会以为必须盯着进度条。

两颗按钮都不是"取消"：关掉它（或点「停留此页」）批改照旧在跑，点「进入下一页」只是顺手翻一页。
**末页与单页题不弹这个窗**——后面没有"下一页"可去，弹出来只有一颗"知道了"能按，那是打扰。

## 会话状态的两处收缩

- 删掉 `openResults`（"返回编辑"时暂存的那份结果）。它存在的唯一目的是区分"放开过但没改"与"放开过且改了"，
  好决定该不该自动提交——自动提交没了，它就没有用途。**「返回编辑」现在不丢结果**，只把这一页变成可写；
  结果真正作废的时机收紧成一个：**用户改了一个字**（判据是草稿与那份结果的 `answer` 是否一字不差，
  改回原样也不算作废）。这样"放开看一眼、一个字不改又翻回来"不会白花那一次调用。
- 新增 `pageResultDropped`：术语栏的「重新作答」要的是"把这一组的结果真的丢掉"，
  这件事与"放开重写"**不是同一件**——术语栏"显示输入框还是显示判分"就是由"这一页有没有结果"决定的，
  结果留着按了等于没按。两个动作各管一处，而不是让 `pageUnlocked` 在两处各意味着一件事。

## 顺带修掉的：切栏之后"看到的东西不变"

用户报过："批改界面下，切换导航栏后，回到文章模式时，不要恢复到批改前的空白状态，而是保留记忆，
相当于切换之后切换回来，看到的东西不变。"

根因是 `selectTab` 里一句 `setViewingGradeId(null)`（"正在看这一页的第几次批改"）。
它把"我正在看第 2 次"这条记忆当成"练习页的临时看法"抹掉了，于是切回来看到的是作答框，
用户以为批改结果被清空。现在这个 id **跨切栏保留**，只有三种情况会让它失效：用户点「回到作答」、
翻到别的页（历史是"这一页的"）、或者它解析不出来（换了题目、记录被上限裁掉）——
解析那一处按"当前题目 + 当前页"过滤，因此留着一个暂时对不上的 id 也显示不出错东西。

## 放弃的东西

- **"忘按提交"这条路出现了**：写完一页直接翻走，那一页不会自动批。接受它，是因为另一种选择
  （替用户决定何时花钱）已经被证明更糟。
- **`edited` / `modified` 两档状态没了**：界面上因此不再有"已修改 · 待提交"这种说法，
  按钮也不再叫「提交批改（手动）」——全站只有一个「提交批改」。
