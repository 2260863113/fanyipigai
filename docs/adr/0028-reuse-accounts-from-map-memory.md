# 账号体系复用「地图记忆」：D1 + 浏览器端 PBKDF2，提交批改要登录

## 决定

把「地图记忆」那套账号体系搬进这个站：**Cloudflare D1 存账号与会话**、
**Pages Functions 提供接口**、前端做登录/注册弹窗、个人中心、留言板、用户管理与访问日志。
用户的要求是：

> 用户可以自行登录，也可以在"提交批改"时，弹出登录/注册窗口（如果没有登录，那么提交就失败）

因此「提交批改」多了一道门：**没登录就什么都不做**——不标记批改中、不发请求，
只弹出登录/注册窗并写清原因。浏览（选题、看原文与参考译文、看留言板）**不需要登录**。

## 密码：明文从不上网（照搬来源项目，别改）

- 注册：浏览器取 16 字节随机盐，算 **PBKDF2-SHA-256（120000 次迭代、256 位）**，
  只把 `{algorithm, salt, hash, iterations}` 发给服务端。
- 登录：先 `POST /api/auth/salt` 拿这个账号的盐（用户名不存在时返回**固定的假盐**，
  免得被用来枚举哪些名字注册过），在浏览器里算一遍再发去比对。
- 两道防线必须同时成立：**迭代次数下限**（服务端拒绝 < 120000 的哈希，否则一个弱哈希就能换到合法会话）
  与**不区分失败原因**（"用户不存在"和"密码错"回同一句话，挡枚举）。

代价写清楚：服务端**无法**做密码强度校验之外的事（比如"密码是否泄露过"），
也**无法**在用户忘记密码时帮他找回——因为服务端根本没存明文，也没有邮箱。
「找回密码」因此在「明确不做」里（与来源项目一致）。

## 会话：Bearer token，不是 cookie

token 是 32 字节随机十六进制，发给浏览器保存（`localStorage`，
键 `translation-practice.session.v1`——前缀沿用本站既有的那一套，见 README 的说明）；
**库里只存它的 SHA-256 摘要**，因此库被看到也拿不到能用的登录态。有效期 30 天。

⚠️ 已知代价：它不是 `HttpOnly` cookie，**XSS 能把它偷走**。
之所以还是这么选：这个站没有服务端渲染、没有跨域需求，而 cookie 会引入
SameSite / CSRF / 域名绑定三件事；token 在 `Authorization` 头里是最省事的。
（早先那道访问口令用过 `HttpOnly` cookie，口令门撤掉后那套代码已经删了，见 ADR 0027。）

## 登录门放在哪儿

- **界面这一层**（`App.tsx` 的 `submitPage`）：放在**篇幅门与去重门之后**。
  那两道管的是"你写的这段本身行不行"，是用户当场能改的事；等它过了再谈"你得先登录"，
  少一次白弹窗。
- **服务端这一层**（`src/server/guard.ts` 的 `requireSession`）：**这里才是边界**。
  界面藏起来的东西改一行 JS 就能打开；`/api/judge` 前面这道检查不受前端影响。

## 复用了什么、改写了什么

**照搬**（结构、SQL、校验规则、失败文案都保留）：`http/auth/guard/rows/validate/limits/profile/board`
七个服务端模块、`functions/api/{auth,board,admin}` 与 `/api/visit`、以及 `schema.sql` 里
users / sessions / board_posts / board_replies / access_logs 五张表。

**去掉**：`hometown`（那是地图站的"家乡"，与本项目无关）、`leaderboard` 与 `announcements`
两张表、以及相关的校验与接口。

**改写**：前端。来源项目是原生 DOM（`ui/authPanel.ts` 等），这里是 React，
因此界面重写为 `src/components/auth/*`（store + 弹窗）、`ProfileView`、`BoardView`、`AdminView`；
沿用它的三件约定：头像前端压到 20KB 以内、改密码要**先算旧密码的哈希**、
用户名归一化前后端**逐字一致**（两处一起改，否则会出现"界面说可以、提交却被拒"）。

## 管理权限没有自助入口

`is_admin` 只能由站主用 SQL 指定（注册接口一律写 0）：

```
npx wrangler d1 execute fanyipigai-db --remote \
  --command "UPDATE users SET is_admin = 1 WHERE username = '你的用户名'"
```

理由与来源项目一致：一个练习站不需要"申请成为管理员"这种流程，
而任何自助入口都要再配一套审批/防冒用，收益为零、风险不小。

## 练习记录**没有**跟着账号走

题库、参考译文、每次批改的记录仍然全部在这台浏览器的 `localStorage` 里
（换台电脑就没有）。用户这次要的是"账号 + 登录 + 留言板 + 管理 + 日志"，
没要求把练习记录搬上服务端；那是另一件事（D1 版"云同步"，见 README 的「尚未开始」）。
个人中心里如实写着"本机存着 N 条练习记录"，免得用户以为它跟着账号走。

## 验证

- 冒烟 `npm run smoke` **828 项**通过：新增 32 项账号相关的纯函数与安全细节
  （用户名归一化、密码哈希结构、头像上限、改密码的旧哈希比对、留言长度、
  **会话写库存的是摘要而不是 token 明文**），以及 4 项登录门
  （没登录按提交 → **一次接口都没调**、顶栏有登录入口、作答框还在、留言板入口可见）。
- `node scripts/verify-accounts.mjs` 对着**本地 D1 + 真实 workerd** 跑 **42 项**：
  注册/重名/弱哈希/登录/枚举防护/会话/改资料/改密码/发帖回复/只能删自己的/管理权限
  （普通账号 403）/日志明细/流量分桶/访问上报/退出后 token 立即失效。
- 仍需在真实浏览器里点一遍：按「提交批改」是否真的弹出登录窗
  （探针里断言不了——它提交之后还会点别处，会顺手把弹窗关掉，那本来就是弹窗该有的行为），
  以及部署到线上之后的同一条路径。
