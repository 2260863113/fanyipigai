# 批改用结构化数据描述，而不是让 AI 直接生成带标记的 HTML

批改结果由 AI 生成。我们让它返回一组「错误对象」——每处错误包含改法类型、错误分类、锚点、原文、改正文本、颜色、简短理由——由前端按类型渲染荧光笔底色、上方小字、插入标记与调序弧线。**没有**让 AI 直接返回带 `<del>`、`style` 的现成 HTML 片段。

## 为什么

让 AI 吐 HTML 会快很多，但代价是：AI 写错一个标签，整页就白屏或错位，而长段落里这件事几乎必然发生。更麻烦的是，把 AI 的输出当标记语言直接贴进页面，等于把模型输出当代码执行，安全上也不可接受。结构化数据把「排版」这件事从 AI 手里拿回来交给程序，AI 只需要把「哪里错了、该改成什么」说清楚。

## 定位方案：字符序号区间 + 原文片段双重校验

锚点同时给出「字符序号区间」和「该区间内的原文片段」。程序渲染前先验证两者是否吻合，不吻合就判定该处批注无效并拒绝渲染。

放弃的两个替代方案：

- **只给"哪个词"**：同一个词在句中出现两次（两个 `the`）就会标错位置，且无法表达"第 3 句里的那个词"。
- **按句子 + 句内词序号**：比全篇字符序号好数，但仍无法处理句内重复词，且"跨多个词的语序调换"很难表达。

双重校验的价值在于：AI 数错位置是常见错误，而原文片段让程序**自己就能发现**这个错误，不必依赖人工核对。
