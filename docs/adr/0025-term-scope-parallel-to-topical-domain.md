# 术语范围：术语栏另开一张与话题领域平行的表

## 决定

术语栏的出题分组**不再用「话题领域」**（社会／经济／文化／生态／科技那张全站共用的表），
而是用它**自己的一张封闭表**：**术语范围**，目前两个取值——**国内机关名称**、**国际机关名称**。

两张表**平行、不互相隶属、不共用任何一条数据**：

| | 话题领域 | 术语范围 |
| --- | --- | --- |
| 谁在用 | 文章栏、句子栏、AI 出题的预设 | 只有术语栏 |
| 取值 | 社会／经济／文化／生态／科技（五个） | 国内机关名称／国际机关名称（两个） |
| 界面上的叫法 | 「领域」 | 「范围」 |
| 代码 | `articles.ts` 的 `ARTICLE_DOMAINS` | `term-scopes.ts` 的 `TERM_SCOPES` |

## 为什么

CONTEXT.md 早先写着"话题领域是一张封闭的表，**全站共用**，术语库按它分组"。
那条口径在术语库还是"按板块分组的政论固定表述"时是对的。
第 13 轮术语库整批换成**机关名称**之后，它就不成立了：

- `国内机构.docx` 里是党中央、全国人大、国务院各部委、地方各级人民政府……；
  `国际机构.docx` 里是联合国各机构、专门机构、区域性组织……。
  **它们没有"社会／经济／文化／生态／科技"这种板块属性**——这两个文件本身就是两种不同的分类法。
- 硬要沿用那张表，就得替 **143 条**术语**一条条凭空编一个板块**（"最高人民法院"算社会还是科技？）。
  编出来的那个「领域」是假的：用户按它筛出来的东西不会有任何规律，
  而"领域"这个词在全站的含义也会立刻分裂成两套。

用户对这一题的答复正是这句话："术语模式用自己的领域，与社会经济这些领域平行。"
于是把它定成一个**平行的第二张表**，而不是"术语栏里再挂一个筛选器"：

- 它决定**出题的粒度**（一张范围 = 一道题 = 一个题库单位，有份数、有页码）；
- 因此"术语题按范围编号与分页"这件事有了依据，而不是靠一个可选筛选器；
- 界面上按钮写「范围」而不是「领域」——同一个词指两张表，是这个项目反复踩过的坑。

## 连带

- **ADR 0010 里"术语库随之少了 26 条词"那句话作废**（那条 ADR 记的是领域表从八个收敛到五个的后果）：
  术语库现在既不按板块分组，也不再看那张表。那 26 条与后来那 43 条一起归档在
  `src/domain/legacy-terms.ts`（见 ADR 0023）。
- `DomainSelect.tsx` 里那句注释"术语题与'自己贴的题'没有这两个控件"要改成
  "术语题有自己的那一对控件（范围 + 方向），只是与领域无关"。
- 句子栏仍然只给「领域」、不给方向（方向由句子本身决定）——它归话题领域那一侧，不受影响。

## 代价

- 术语栏与文章栏的"分组控件"长得像（都紧挨「原文」、都管出题范围），但**数据互不相干**：
  以后往任一张表里加一项，另一张表**一个字都不动**。这正是要的效果，代价是读代码时
  必须先分清"这个 range 是哪一张表"（`ARTICLE_DOMAINS` 还是 `TERM_SCOPES`）。
- 术语范围目前只有两个，且**不能由用户自己加**（与话题领域一样是封闭表）。
  要加一个范围：把 docx 放进仓库根目录 + 在 `build-terms.mjs` 的 `SCOPES` 里加一条 +
  重跑 `node scripts/build-terms.mjs --write`（三步写在 `term-scopes.ts` 的文件头）。
