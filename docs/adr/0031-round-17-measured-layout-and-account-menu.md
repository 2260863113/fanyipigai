# 第 17 条那一批：版式靠测量、收藏分两种、看板手写 SVG、账号入口收进下拉栏

> **状态**：已落地。这一批是用户一次给的九条要求，落在四个互不相干的地方，因此一条 ADR 记四件事。
> 涉及的文件：`src/components/pane-heads.ts`、`src/components/term-above-fit.ts`、
> `src/components/TrafficChart.tsx` + `src/domain/traffic.ts`、
> `src/components/TopBar.tsx` + `src/components/auth/PasswordModal.tsx` + `src/components/admin-tabs.ts`、
> `src/domain/favorites.ts` + `src/components/FavoritesView.tsx` + `src/components/CompareLines.tsx`，
> 以及 `src/styles.css` 里那几段带"第 17 条"字样的注释。

## 决定

1. **要"一样高 / 一行放得下"的地方，一律量一遍再落，不写死数字**：
   「原文」与「我的译文」两个标题栏的高度（`--pane-head-h`，按当帧内容最高的那一栏算）、
   术语模式两栏每一格的高度（把原文栏页脚的高度从译文栏正文里让出来）、
   术语更正那一行能不能一行放下（量文字宽度，再决定"左右加空格撑开标记段"还是"折行"）。
2. **收藏分成两种**，用判别联合（`kind: 'mark' | 'sentence'`）：精修档收藏"某一处批注"，
   大改档收藏"一整句"（原文 / 我的译文 / 修改译文 / 解释四部分）。
3. **流量看板手写 SVG 折线**，不引 ECharts。
4. **管理三屏（用户／日志／公告）与改密码收进「个人中心」下拉栏**，导航里那颗常驻的「管理」撤掉。

## 一、版式为什么必须"量"，不能"写死"

这一批有四处要求是同一个形状：**"这两样要一样"或者"这一行要装得下"**。
它们的共同点是——**答案取决于当帧的内容与窗口宽度**，因此拿一个写死的像素值去凑是凑不准的：

| 要求 | 写死会怎样（实测） | 现在的做法 |
| --- | --- | --- |
| 两个标题栏等高 | 原文栏 46px、译文栏 51px（差在"最矮的控件"上：领域下拉 29 vs 分段开关 34）；判分后译文栏还会多出「批改记录」+ 两枚芯片 + 「返回编辑」，一段放不下就折成两行 → 差到 82px | 每帧量一遍两栏标题栏**内容需要**的高度，取最大的写成 `--pane-head-h`，两栏一起用（`pane-heads.ts`） |
| 术语两栏每格等高 | 原文栏正文 710px、译文栏 760px（原文栏底下还有翻页那一条 55px），于是每格 68 vs 73——十行下来第十格差 50px | 给译文栏正文加一段与页脚等高的下内边距，两栏可用高度相等（`--term-foot-h` 只写一次） |
| 参考译文一行装下 | 宽度上限写死 46%（=316px），把明明放得下的 410px 官方译名硬折成两行 | 上限放宽到 64%，题干那一侧留 `min-width: 11em`；超出的（手册那三个板块里上千像素的整句）本来就放不下，照旧折行 |
| 更正一行写完 | 早先 `max-width: 100%`（=被划掉那个词的宽度），一个词写错时上方那行更正会被折成五六行 | 屏幕外的量尺量出"一行要多少宽"，再决定：放得下 → `nowrap` + 左右加空格把标记段撑到正好包住它；放不下 → 折行并把宽度压在整行以内 |

两条实现上的取舍值得单独记：

- **`scrollHeight` 量不出"内容真正需要多少"**：盒子已被撑高时它至少等于 `clientHeight`，
  于是量出来的永远是上一轮那个高度、只会越量越高。因此每一轮都**先把变量撤掉**再量、量完写回
  （两步都在同一帧、绘制之前，屏幕上不闪）。
- **量文字宽度要用屏幕外的量尺**（`measureOneLineWidth`），不能读元素自己的 `scrollWidth`：
  折行状态下读到的是折行后的宽度，判据会自己骗自己，出现"折行 → 看着放得下 → 改成一行 → 又放不下"的来回跳。

另有一条**已知取舍**：判分之后译文栏标题栏那几样（批改记录 + 组/页/条数 + 本地判分 + 视图开关 + 返回编辑）
加起来比一整行宽约 92px，因此那一档**会折成两行**（118px）。两栏仍然等高（"等高"这条要求成立），
代价是十行每行少 6.7px。要让它保持一行只有两条路：把「本地判分」这枚芯片挪走、或者砍掉芯片里的「第 N 页」——
两样都是用户点名要看的信息（"哪一组 · 第几页 · 几条"与"本地判分"），因此**没有动**，
把这条取舍写在这里而不是悄悄改掉。

## 二、收藏为什么会变成两种

第 5 条要的是"大改档每一句原文后面加一个收藏按钮，点了收藏**这一句**：
原文、译文、修改后的译文、解释四大部分"。它与早先那种收藏（精修档点某处批注：
"改前 / 改后 / 为什么"）**收藏的东西不一样**：那边收藏的是**一处改动**，整句只是它的上下文；
这边**整句就是对象**，四部分一样都不能少。

因此 `Favorite` 改成一个判别联合，共有的一半（题号、方向、话题、页号、什么时候存的、为什么）放在基类型里，
两种各自带自己的字段。三条附带的决定：

- **存储键不动**（`translation-practice.favorites`，从建站起没改过），老条目**没有 `kind`**，
  读的时候一律当作 `'mark'`——因此老收藏一条都不会丢。
- **整句收藏的编号按文字摘要算**（`textKey`，djb2），不按"第几句"：同一个题号、同一页可以**重新大改一次**，
  而重新大改之后句子顺序未必与上次相同——按序号编号的话，第二次点「收藏」会把上一次**另一句**取消掉。
- **两种收藏在收藏页画法不同**：`mark` 是"改前 / 改后两行、只给那一处上色"；
  `sentence` 是"原文 / 我的译文 / 修改译文 / 解释四行摊开"，解释那一行走 `withCircledBreaks`
  （按分号断行、带圈号）——与大改视图里印在句子下面的那段说明**同一个排版**。

## 三、流量看板为什么手写 SVG

用户要求"流量板需要形同「地图记忆」一样的折线图显示"。那边是 ECharts（`ui/trafficChart.ts` + `ui/trafficSeries.ts`）。
这边**不引它**，理由有三条：

1. 只需要"一条折线 + 圆点 + 一层渐变面积 + 虚线网格 + 悬停给那一桶的访问量"，手写 SVG 一百行左右就够；
   ECharts 是约 1MB 未压缩的依赖，为一张只读图引进来不划算。
2. 那边要在 JS 里读 `getComputedStyle` 拿颜色（ECharts 的 option 不认 CSS 变量）；SVG 里颜色可以直接写
   `var(--accent)`，**明暗主题一换，图上的颜色自己就跟着换**，不需要第二份颜色表。
3. **顺带修掉一个真问题**：这边原先那个"流量板"画的是一排 `.admin-bar` 方块，
   而 `.admin-bar` / `.admin-bar-col` 这两条样式**在两张样式表里都没有**——
   也就是说屏幕上那一块其实是一排没有宽度、没有颜色的块。

桶标签一律**只做正则拆解**（`2026-09-26` / `2026-09-26 14:00` → 月/日/时），
**绝不用 `new Date(label)` 解析**：那会把一个不含时区的日历串按浏览器时区解释，
在非 +08 的机器上整条折线的刻度就跟着漂（服务端已经按站点时区生成好了标签、也补过 0 桶，客户端只负责画）。

## 四、账号入口为什么收进下拉栏

用户原话："对于日志管理，用户管理，发布公告，个人中心，修改密码这些内容，
都放到点击个人中心后的下拉栏中，就跟「地图记忆」一样。"因此：

- 顶栏导航里那颗常驻的「管理」**撤掉**（它只给管理员看，却占着所有人的导航位）；
- 登录之后那颗「头像 + 用户名」变成**菜单触发器**，里面是
  「个人中心 / 修改密码 /（管理员才有）用户管理 · 日志管理 · 发布公告 / 退出登录」；
- **「修改密码」从个人中心那张卡片里搬出来单独成一件**（三格：旧密码 / 新密码 / 确认新密码），
  个人中心那一屏只剩"改名字 + 换头像"——与「地图记忆」的个人资料卡一致；
- 「当前看管理页哪一屏」这个状态**上移到 App**：下拉栏点「用户管理」要直接落到那一屏，
  状态锁在 AdminView 里就只能落在默认屏上、再让用户自己点一次；
- 那一屏的分段按钮名字统一成用户点名的说法（原来的「日志记录」→「**日志管理**」），
  免得菜单里叫一个名、页面里叫另一个名。

界面上的 `isAdmin` 判断**只是"不给看"**：真正的权限仍在服务端的 `requireAdmin`（这条没有变）。

## 五、日志里的"完整设备名"

用户要求"对于日志记录登录的游客，对他们的设备名称的完整名称记录下来"。查下来：
**库里一直存着完整的 User-Agent**（`access_logs.ua` 存的就是请求头原样，游客同样存），
缺的从来不是"记录"而是"显示"——日志那一列原先只画 `shortenUserAgent` 那四个字
（「Chrome · Windows」），完整串只藏在悬停提示里。因此这一条**没有改库、没有改接口**，只改显示：
每一行把三样一起给出来——短名字（扫描用）、**带版本号与机型的人话版本**
（`describeDevice().label`，如「Edge 140 · Windows 10/11 · 电脑」）、**完整的 UA 原样**
（可选中、可折行，不再用省略号裁掉）。

解析规则与 `shortenUserAgent` 同一套取舍：不引 UA 解析库，认不出来的部分照实空着，
**宁可难看也不假装认出来了**。Windows 的 UA 只给 `Windows NT 10.0`——11 与 10 共用这一个号，
因此照实写「10/11」，不猜。
